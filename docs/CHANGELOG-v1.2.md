# Documentation Changelog — Version 1.2

**Updated:** 2026-07-18  
**Status:** Finalized product and MVP documentation

## Finalized

- Defined the completed product as a three-layer autonomous software-development operating model.
- Clarified that simulation-first is the MVP delivery strategy, not the final product boundary.
- Added the canonical user journey from login through merge decision.
- Added the exact **Start this Project** preflight, idempotency, and workflow contract.
- Added Layer 1 Planning and Project Intelligence responsibilities and outputs.
- Added Layer 2 Development Execution responsibilities, ticket leasing, repository workflow, and simulated MVP artifacts.
- Added Layer 3 Independent QA and Merge Advisory responsibilities and structured decision outputs.
- Established `develop` as the only normal automated pull-request target and prohibited agent PRs to `main`.
- Added deterministic next-workable-ticket eligibility, ranking, and lease rules.
- Added real Notion publication and idempotent reconciliation to the MVP.
- Added the merge-risk assessment schema and user decision options.
- Added an event-driven interactive 3D office as a primary product interface.
- Required an accessible dashboard with equivalent information and controls.
- Finalized a Laravel 13 modular-monolith MVP with React, PostgreSQL, Redis, and React Three Fiber.
- Added MVP screens, modules, APIs, scenarios, testing, security, operational requirements, delivery phases, and Definition of Done.
- Added explicit post-MVP entry criteria for introducing real coding providers.

## Preserved

- Provider-independent architecture.
- Deterministic workflow infrastructure.
- Simulation as a first-class execution provider.
- Approved documents as the architecture and engineering baseline.
- Notion as the task-level source of truth.
- Human approval gates.
- Low, Medium, and High reasoning policy.
- Evidence classification and separation of reported, observed, and actual state.
- Reliability, idempotency, recovery, security, observability, and cost controls.
