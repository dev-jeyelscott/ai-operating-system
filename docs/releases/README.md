# Release documentation

Versioned release notes are added only after a candidate has current automated
evidence and named human approvals. Each release note records the candidate
commit, MVP scope, real and simulated capabilities, migration inventory,
configuration changes, validation and security status, accessibility status,
known risks, upgrade and rollback procedures, recovery references, and
contributors and approvers.

No release note may imply that a simulated repository write, pull request, CI
result, merge, or deployment was verified. Real provider execution requires a
later threat-model review.
