# Security Policy

Do not open a public issue containing credentials, private project data,
exploitable security details, or user information.

Security reports should include:

- Affected component
- Reproduction conditions
- Security impact
- Required privileges
- Evidence with all credentials redacted
- Suggested mitigation when available

The security architecture baseline is documented in:

- `docs/security/threat-model.md`
- `docs/security/abuse-case-register.md`

No implementation may claim that simulated evidence proves tests, review,
merge, deployment, or production verification.
